# Patchdeck v1.7.4

Release date: 2026-06-03

## Summary
Deferred (phased) updates no longer inflate the update count. **Non-breaking — upgrade in place, no config changes** (adds one additive DB column automatically).

## Changed
- **Phased / deferred updates are detected reliably and shown separately.** Ubuntu rolls some updates out gradually ("phased"); they appear in `apt list --upgradable` but `apt upgrade`/`dist-upgrade` won't install them yet. Patchdeck previously counted them (the old `(phased %)` heuristic didn't match, since `apt list` doesn't tag phasing on Ubuntu). Now the scan also runs `apt-get -s dist-upgrade` and uses apt's own explicit report ("deferred due to phasing" / "kept back") as the source of truth:
  - The **count reflects only actionable updates** — what Apply (`dist-upgrade`) will actually install. A host with only phased updates now reads **"Up to date"** instead of showing a count that Apply can't clear.
  - Deferred updates are surfaced as a muted **"N deferred (phased)"** tag on the host card, with a tooltip listing them ("Ubuntu is phasing these in; they'll apply automatically later").
  - This also correctly *keeps* counting packages that plain `apt upgrade` holds back for new dependencies — `dist-upgrade` installs those, so they remain actionable.

## How it works
- Scan runs `apt-get -s dist-upgrade` (a dry run — changes nothing) and parses the deferred blocks; deferred packages are stored separately (`deferred_packages`) from the actionable `packages`, so every existing count/notification stays correct by construction.
- Falls back to counting all upgradable as actionable if the simulation is unavailable (never over-defers).
