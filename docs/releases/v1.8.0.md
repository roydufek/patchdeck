# v1.8.0

**Native Go notifications — Apprise/python removed from the image.** Plus the v1.7.7
service-restart fixes (folded in; v1.7.7 never shipped a standalone image).

## Why

The runtime image bundled a full CPython interpreter solely to run the Apprise CLI for
sending notifications. That dragged python's entire CVE stream into the image — including
CVEs whose only upstream fix is a python *prerelease* (e.g. CVE-2026-7210, fixed only in
3.15.0b2), which can't be cleared by a stable base bump. The recurring "python tax" blocked
CI's fixable-HIGH/CRITICAL gate. Removing python eliminates that surface permanently.

## Notifications — now native

- New `notify` package delivers over HTTP(S)/SMTP directly in Go. **No python, no Apprise,
  no external binary.** Supported schemes (Apprise-style URLs, so existing configs keep
  working): `gotify(s)`, `ntfy(s)`, `discord`, `tgram`/`telegram`, `slack`, `pover`/`pushover`,
  `mailto(s)` (SMTP), and `json(s)`/`form(s)` generic webhooks.
- The configured destination is still an `apprise_url` setting (same key, same UX). The
  settings page now lists the supported schemes (delivery is always available — there's no
  external runtime to be missing).
- Errors are scrubbed of the target URL so tokens/passwords never reach logs or API
  responses. Header values (ntfy Title, email From/Subject) are CRLF-sanitized.
- Unsupported schemes are rejected at save/test time with the supported list.
- **Image:** runtime base is now plain `alpine` (ca-certificates + su-exec) instead of
  `python:3.x-alpine` + pip + apprise — tens of MB smaller, far less attack surface.
- Removed `PATCHDECK_APPRISE_BIN` (no binary to point at).

## Service-restart fixes (from v1.7.7)

- Probe-then-commit privilege escalation: `systemctl restart` of a refused/missing unit now
  surfaces its **real** error instead of the misleading "privilege escalation failed".
- Per-service restart (one failing unit no longer sinks the batch); systemd manager →
  `daemon-reexec`; connection drop mid-restart reported as likely-restarted.

## Tests
- `notify/notify_test.go` — URL→request mapping for every scheme (gotify/ntfy/discord/
  telegram/slack/pushover/webhook), email parsing + header-injection guard, unsupported-scheme
  and empty-target handling.
- `sshx/connection_lost_test.go` — restart/escalation classification (from v1.7.7).

## Migration notes
- **No DB change.** The `apprise_url` setting and event toggles are unchanged.
- If you used an exotic Apprise backend not in the list above, switch the URL to one of the
  supported schemes (or a generic `jsons://` webhook). Open an issue to request another.
- Email URLs must specify the SMTP host explicitly (`mailtos://user:pass@smtp.host/?to=…`);
  there is no provider auto-inference.
