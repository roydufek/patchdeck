# v1.8.11

Fix: **stop browsers serving a stale frontend after a deploy.** The SPA was served with no
cache headers, so browsers (mobile Safari especially) heuristically cached `index.html` and
kept loading an *old* JS bundle even after the server was updated — making frontend fixes look
like they "didn't take."

## Background

Patchdeck's static handler served everything through a bare `http.FileServer` with **no
`Cache-Control`**. Two consequences:

- `index.html` — the entry point that references the current content-hashed bundle
  (`assets/index-<hash>.js`) — got heuristically cached. After a deploy, a returning browser
  re-used the cached `index.html`, which pointed at the *previous* bundle, so the user saw the
  old UI until they manually cleared their cache. (This is exactly what made v1.8.10's restart
  fixes appear absent on an already-visited device: the server was serving 1.8.10, the browser
  was executing a cached older bundle.)
- The hashed assets weren't marked cacheable either, so they weren't cached as aggressively as
  they safely could be.

## Change

The static handler ([`api/cmd/server/main.go`](../../api/cmd/server/main.go)) now sets
`Cache-Control` per the standard SPA pattern:

- **`/assets/*`** (Vite's content-hashed JS/CSS) → `public, max-age=31536000, immutable`. The
  URL changes whenever the content does, so caching them forever is safe and fast.
- **`index.html`** and the SPA fallback → `no-cache` (revalidate on every load). Combined with
  the `Last-Modified` the file server already sends, the browser makes a conditional request
  and gets a cheap `304` when unchanged — but always picks up a new `index.html` (and thus the
  new bundle) immediately after a deploy. **No more clearing cache to see an update.**

## Notes

- Backend-only; no DB, config, or frontend change.
- Existing behavior after this ships once: the *first* load still needs a fresh `index.html`
  (a hard refresh / private tab / cache-clear) to escape the old cached copy; from then on,
  every future deploy is picked up automatically.
