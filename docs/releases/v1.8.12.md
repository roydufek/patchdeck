# v1.8.12

Feature: **opt-in restart of needrestart-deferred units, to avoid a reboot** — run detached so a
connection flap can't interrupt them, with reconnect-retry recovery afterward.

## Background

v1.8.10 correctly stopped presenting override_rc units (dbus, systemd-logind, networking,
docker, …) as ordinary restartable services and moved them to a "Reboot to apply" card. But
that was too blunt: needrestart's `override_rc` means *"don't auto-restart; let the admin
choose,"* not *"never restart."* Restarting `systemd-logind` (and most of these) is perfectly
safe — needrestart itself restarts them when you select them interactively — and a reboot is
often more disruptive than the service restart. Only **dbus** is a true exception.

## Change

The deferred card now offers, per unit, a **"Restart selected"** action alongside the reboot —
you pick which units to restart instead of rebooting.

**Backend** ([`internal/sshx/client.go`](../../api/internal/sshx/client.go), new
`RestartDeferredDetached`; `POST /api/hosts/{id}/restart-deferred`). Per unit:

- **Use needrestart's `restart.d` handler when the unit has one** — that *is* needrestart's own
  handling. Mandatory for **dbus/dbus-broker**: the handler restarts the bus *and* re-registers
  its clients (logind, …). If a dbus-family unit has **no** handler, it is refused →
  reboot-required (a naive bus restart severs it and locks out SSH — the original Nova incident).
- **Everything else** (logind, networking, docker, gettys, …) → a plain `systemctl restart` run
  **detached** via `systemd-run --collect`, so a unit whose restart flaps the connection still
  runs to completion regardless of the SSH session. This is exactly the restart needrestart does
  for a unit with no special handler — just decoupled from the session.

**Recovery** — after dispatching, patchdeck starts the existing recovery monitor (server-side
reconnect loop with attempt counts and a timeout), so it reconnects, confirms the host is back,
and re-scans. ~120s cap (services recover fast); it reports "recovered" or "timed out" and never
hangs.

**Frontend** ([`HostDetails.jsx`](../../web/src/components/HostDetails.jsx)) — the deferred card
gains checkboxes (opt-in, unchecked by default, mirroring needrestart's pre-deselected screen),
a "Restart selected" button, and the reboot fallback. dbus units are tagged "via handler." The
old dbus-only "coordinated restart" link is folded into this unified flow.

## The dbus guardrail (unchanged rule, now enforced in the new path too)

Detaching a restart makes it *complete*; it does not make it *safe*. Restarting dbus severs the
bus and strands its clients no matter how it's launched — so dbus can **only** be restarted by
its coordinated handler (which also restarts the clients), or by a reboot. It never takes the
generic detached path. Everything else is safe detached, because restarting *them* strands
nothing.

## Notes

- No DB or config change. New endpoint reuses `RestartResult` (+ its `reboot_required` for a
  dbus-with-no-handler).
- Tests: `isDbusFamily`, `deferredRestartCmd` (assert dbus never gets a generic/detached restart;
  logind always does, never reboot-deferred).
- Verified the detached mechanic on a real Debian 13 host (`systemd-run`-launched restart
  produces a real PID change, auto-collects, session unaffected).
