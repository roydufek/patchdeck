# Patchdeck v1.5.0

Release date: 2026-06-01

## Summary
Security hardening — closes the remaining `SECURITY_REVIEW.md` gaps: brute-force protection on login and strict validation of service names to prevent command injection.

## Security
- **Login brute-force lockout.** Added a per-client-IP sliding-window limiter (`ratelimit.LoginLimiter`): after 8 failed attempts within 15 minutes, further attempts return `429 Too Many Requests` with a `Retry-After` header until the window clears. Failures are counted for bad username, bad password, and bad TOTP/recovery code; a successful login resets the counter. The existing limiter only throttled per-host operations, not authentication.
  - Client IP is resolved via `X-Forwarded-For` / `X-Real-IP` (set by Traefik), falling back to `RemoteAddr`.
- **Service-name command-injection guard.** `POST /api/hosts/{id}/restart-services` previously passed service names straight into `systemctl restart <names>` on the remote host. Names are now validated against a strict systemd-unit charset (`[A-Za-z0-9._@:\-\\]`), and the request is capped at 100 services. A name containing shell metacharacters is rejected with `400`.

## Notes
