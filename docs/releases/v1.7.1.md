# Patchdeck v1.7.1

Release date: 2026-06-02

## Summary
A correctness, stability, and hardening release from a post-1.7.0 code review. **No breaking changes — upgrade in place, no fresh DB or config changes required.**

## Fixed
- **Scheduler crash safety** — a panic in a job's scan/apply/parse path could crash the whole server (taking the HTTP API down) and leave the run stuck as "running". Job execution now recovers from panics, logs them, and closes the run as failed.
- **Cron correctness:**
  - Weekday `7` now correctly matches Sunday (previously a valid `7` schedule never fired).
  - Day-of-month + day-of-week now follow standard Vixie-cron semantics: when **both** are restricted the tick matches if **either** matches (OR), instead of requiring both (AND).
  - Added scheduler unit tests covering the above.
- **`DeleteHost` no longer orphans run history** — deleting a host now also removes its jobs' `job_runs` rows.
- **Deterministic run-history pruning** — `PruneJobRuns`/`ListJobRuns`/`GetLastJobRun` use a stable `(started_at, id)` ordering so concurrent same-second runs prune/sort predictably.

## Security / hardening
- **Login rate-limiter spoof fix** — `X-Forwarded-For`/`X-Real-IP` are now trusted only when the request's direct peer is a loopback/private proxy (e.g. Traefik). A direct connection can no longer forge those headers to bypass the per-IP brute-force lockout.
- **Apprise argument-injection guard** — the notification target is passed after `--`, so a target beginning with `-` can never be interpreted as an apprise flag.
- **API-token write throttling** — `last_used_at` is updated at most once per minute instead of on every authenticated request, removing a SQLite write-contention path under concurrent API polling.

## UI
- The job card's **"Last run"** now reflects live run history once the Runs panel is opened (it was previously a page-load snapshot that could lag the actual run until a full refresh).

## Docs
- README roadmap refreshed; clarified that notification **sending** already works and the roadmap item is a persisted **delivery log**.
- `.env.example` cleaned up: removed the dead `REGISTRATION_ENABLED` (gone in v1.7.0), added `PATCHDECK_APPRISE_TIMEOUT_SECONDS`.

## Known follow-ups (deferred)
- SSE scan/apply streams don't yet cancel the underlying SSH session when the browser disconnects (bounded by the exec timeout).
- Removing a host that is one of several targets of a multi-host job can delete the whole job.
