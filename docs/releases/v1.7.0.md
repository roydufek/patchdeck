# Patchdeck v1.7.0

Release date: 2026-06-02

## ⚠️ Breaking — fresh start required
The master key is now run through a **key-derivation function (HKDF-SHA256)** instead of being used as raw bytes. This changes the encryption key, so **host SSH credentials stored by earlier versions can no longer be decrypted**. On upgrade, **wipe the data directory** (or delete + re-add hosts) and re-bootstrap. `PATCHDECK_MASTER_KEY` itself is unchanged — only the derivation. (No agents/remote state are affected; this is local DB only.)

## Summary
A polish + security-hardening + scheduler release, following a full code review. Closes the remaining `SECURITY_REVIEW.md`-class gaps, removes dead config, and makes scheduled jobs observable.

## Security
- **Master-key KDF** — the AES-256 key is derived from `PATCHDECK_MASTER_KEY` via HKDF-SHA256 (the whole key contributes; no silent truncation, no raw-ASCII-as-key).
- **Fail-closed SSH host-key verification** — the verifier is now mandatory; there is no code path that silently falls back to ignoring host keys.
- **Sudo password via stdin** — passed to `sudo -S` over stdin instead of the remote command line (no longer visible to `ps`/auditd on the host).
- **API tokens hardened** — validated by an indexed SHA-256 lookup (O(1)) instead of an O(n) bcrypt scan over every token per request.

## Added
- **Scheduled-job run history** — a new `job_runs` table records every execution (status: success/partial/failed, per-host ok/failed counts, detail). Surfaced in the UI: each job shows **last run** + **next run**, with an expandable **Runs** history panel. New `GET /api/jobs/{id}/runs`.
- **Reliable scheduler** — due jobs now run **concurrently** (bounded) with an overlap guard, so a long apply can't block the ticker or delay other jobs; the in-memory dedup map is pruned each tick. `scan_failure` notifications are now sent for failed scheduled scans.

## Changed / Removed
- **Removed `REGISTRATION_ENABLED`** — it only ever gated first-run bootstrap (which is already closed once a user exists), so it was friction with no real effect.

## Fixed (from the code review)
- Frontend: recovery-monitor retry-timer leak; follow-up scans now cancelled on logout/reset (no more spurious "session expired"); stale "Failed to load" banner cleared on recovery; streamed lines keyed by sequence; removed dead Dashboard tag-grouping state + a redundant per-poll `/tags` fetch.
- Backend: manual apply now records an `apply_fail` activity entry; `DeleteHost` cleans up orphaned notification-prefs / host-key-audit rows; CSV export neutralizes spreadsheet formula injection; tightened the service-name allowlist.
