# v1.8.8

Safety: **restarting D-Bus / logind no longer locks you out of the host.** Patchdeck now
delegates these "risky" restarts to needrestart's coordinated handler when the host has one,
and refuses (pointing you to a reboot) when it doesn't — instead of running a naive
`systemctl restart` that severs the session bus and kills SSH access.

## Background

needrestart flags `dbus.service` (and occasionally `systemd-logind`) after a libdbus/glib
upgrade. Patchdeck restarted it the obvious way — `systemctl restart dbus.service` — over the
SSH session, synchronously. On modern systemd that is destructive:

- `systemd-logind` holds a connection to the system D-Bus. Restarting dbus alone severs it.
- PAM's `pam_systemd` registers each SSH login with logind **over dbus**. With logind's bus
  connection dead and nothing to re-establish it, **no new SSH login succeeds** — the operator
  is locked out until a reboot (observed in the field: a host needed a hard reboot to recover).

The old code even masked this: when the restart dropped the connection it reported
"connection dropped … likely restarted" and counted it as **success**, while the box was in
fact bricked for SSH.

## Why needrestart gets it right (and what we now reuse)

When you let needrestart restart dbus interactively, it does **not** run a bare
`systemctl restart`. It runs its own handler at `/etc/needrestart/restart.d/dbus.service`,
which:

1. enumerates the bus's active dependents dynamically (logind, timesyncd, …),
2. restarts dbus, does a `systemctl daemon-reexec`, then **restarts every bus client so they
   reconnect to the new bus**, and
3. runs the whole sequence as a **`systemd-run` transient unit** — a child of PID 1, detached
   from the SSH session's cgroup — so it survives its own session teardown and the host
   recovers.

That coordinated, detached restart is exactly what makes it safe. Patchdeck now delegates to
it rather than reimplementing it.

## Change

**Backend** ([`internal/sshx/client.go`](../../api/internal/sshx/client.go)):

- New `isRiskyRestartUnit` classifies the lockout-dangerous units: `dbus`, `dbus.socket`,
  `dbus-broker`, `systemd-logind` (and their `.service` forms).
- For a risky unit, `RestartServices` now runs
  `DEBIAN_FRONTEND=noninteractive /etc/needrestart/restart.d/<unit>` **if the host has that
  handler** (coordinated, self-detaching restart — the box recovers), and treats the possible
  connection drop as expected.
- If the host has **no** handler (needrestart absent, or no handler for that unit), patchdeck
  **refuses** the restart and returns the unit in a new `reboot_required` field on
  `RestartResult` — it never runs the destructive `systemctl restart`.
- Non-risky units restart exactly as before. The `systemd-user` skip and `systemd`-manager →
  `daemon-reexec` handling are unchanged.

**Frontend** ([`web/src/components/HostDetails.jsx`](../../web/src/components/HostDetails.jsx)):

- A risky unit that stays flagged after a restart attempt (because patchdeck refused it) now
  shows a distinct amber notice — *"Reboot required to apply … restarting the D-Bus bus or
  systemd-logind on a running host would lock out SSH"* — with a **Reboot host to apply**
  button. This is separate from the existing containerd/shim "still flagged" explanation.

**Dependency hygiene (from the periodic audit):**

- `npm audit fix` (non-breaking) to clear the new **postcss** advisory
  (`GHSA-r28c-9q8g-f849`, path traversal in source-map auto-loading). Build-time only — never
  shipped in the runtime image (`npm audit --omit=dev` was already 0). The esbuild/vite
  dev-server advisories remain deferred (they need a breaking Vite 5→8 upgrade and don't ship).

## Validation

Exercised end-to-end against a real Debian 13 host (`arc`) with `dbus.service` genuinely
flagged: the needrestart handler restarted dbus **and** logind (coordinated, ~5 s, as a
transient unit), SSH reconnected cleanly, needrestart cleared the flag, and the host was **not**
rebooted — no collateral impact to docker/samba/tailscaled. A dead-man reboot timer was armed
as insurance and cancelled on success.

## Notes

- No DB or config-schema change. `RestartResult` gains an additive `reboot_required` field.
- The "risky" set is intentionally scoped to the dbus/logind family — the actual lockout
  class. needrestart's own `override_rc` also deselects network daemons, gettys, and docker,
  but those recover on their own and stay directly restartable here (not over-blocked).
