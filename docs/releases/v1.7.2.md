# Patchdeck v1.7.2

Release date: 2026-06-02

## Summary
Small follow-up to v1.7.1: cancel an in-flight **scan** when the operator closes the live view, and add a discoverable version endpoint. **Non-breaking — upgrade in place, no DB or config changes.**

## Fixed
- **Live scan releases its SSH session when you close it.** When the browser disconnects from a scan's live (SSE) stream, Patchdeck now closes its SSH connection to the host immediately (freeing the connection + goroutine) instead of holding it open until the exec-timeout. A `context.Context` is threaded through the sshx streaming path and aborts on `ctx.Done()`. A scan aborted this way is *not* recorded as a failure and fires no failure notification. (Verified on devbox: the session drops within seconds of disconnect vs. the ~minutes it would otherwise hold.) Note: the read-only scan command itself may finish on the host on its own — standard SSH behavior for a non-interactive command not doing I/O — which is harmless.
- **Apply intentionally still runs to completion.** Closing the browser during an `apply` does **not** abort it — interrupting `apt-get dist-upgrade` mid-configure risks leaving dpkg half-installed. The apply finishes server-side (still bounded by the exec timeout); only the live view detaches.

## Added
- **`GET /api/version`** — unauthenticated, returns `{"name":"patchdeck","version":"X.Y.Z"}` so checking what's deployed is a one-liner. (The existing `/healthz` already carried the version; this is the discoverable, API-namespaced home for it.)

## Files changed
- `api/internal/sshx/client.go` (context threaded through run/stream/deadline paths)
- `api/cmd/server/main.go` (`/api/version`; scan stream passes `r.Context()`, apply stream uses `context.Background()`)
- `api/internal/config/config.go` (version bump)

## Notes
- Public non-streaming operations (scheduler scans/applies, connectivity, restart, power) are unchanged — they pass `context.Background()` and remain bounded only by the exec timeout, as before.
