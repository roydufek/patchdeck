# Patchdeck v1.2.0

Release date: 2026-06-01

## Summary
Authentication hardening (backend half of the auth refactor): introduces server-side sessions with an httpOnly cookie, alongside a logout endpoint. Fully additive and backward-compatible — existing Bearer/JWT clients continue to work unchanged. The frontend switches to cookie-based auth in a following release, after which the JWT-in-localStorage and SSE token-in-URL paths are removed.

## Added
- **Server-side sessions** (`sessions` table): opaque high-entropy token, stored as a SHA-256 hash with denormalized username/role for a single-row indexed lookup on every request. Sliding expiry (7-day TTL), lazy expiry cleanup, and a startup purge.
- **httpOnly session cookie** (`pd_session`, `HttpOnly; Secure; SameSite=Lax`) issued on login. Because the browser reaches Patchdeck over HTTPS and EventSource sends cookies automatically, this removes the need to pass the auth token in SSE URLs (the token-in-query path becomes a legacy fallback, to be removed once the frontend is cookie-only).
- **`POST /api/logout`** — deletes the server-side session and clears the cookie (real server-side revocation, which stateless JWTs could not provide).
- Auth middleware (standard + SSE) now accepts the session cookie first, then falls back to the existing Bearer (JWT / `pd_` API token) paths.
- Login response now includes `{ user: { username, role } }` for the upcoming cookie-based frontend.
