# Patchdeck v1.6.0

Release date: 2026-06-01

## Summary
Connectivity-status UX overhaul. The dashboard's connection dot was binary (green/red) and driven by a 5-second live SSH check that frequently timed out on reachable-but-slow hosts (e.g. over a tailnet), falsely flagging healthy, freshly-scanned hosts as "Disconnected." This release makes the indicator honest and informative, and treats connectivity and scan-freshness as the distinct signals they are.

## Changed
- **Four-state connection indicator** (replaces green/red binary):
  - 🟢 **Connected** — live quick-check succeeded.
  - 🟡 **Checking…** — a live check is in flight; the dot shows a glowing amber ring (instead of flipping to a misleading red/green) while keeping the last-known color underneath.
  - 🟡 **Unverified — slow** — the quick-check *timed out* but the host's last scan succeeded recently, so it's reachable, just slow to answer. Amber, not red.
  - 🔴 **Disconnected** — reserved for *hard* failures (connection refused, no route, auth failure, host-key mismatch) — genuinely actionable.
- **Quick-check timeout raised 5s → 15s** (configurable via `PATCHDECK_CONNECTIVITY_TIMEOUT_SECONDS`), so slow-but-reachable hosts pass instead of false-timing-out.
- **Summary tiles are tone-aware**: only hard failures count toward "Needs attention"; "slow/unverified" and "checking" no longer inflate the alarm count.
- The expanded host-detail Connection card uses the same color scheme.

## Why
This was the most likely root of the "flickering status colors" / "scans were fine but it showed disconnected" experience: a too-aggressive timeout that randomly passed or failed, shown as an alarming red. Combined with the v1.4.0 fix (no more per-refresh connectivity race), the indicator is now stable *and* truthful.

## Added
- `PATCHDECK_CONNECTIVITY_TIMEOUT_SECONDS` config (default 15).
- `connectivityChecking` state threaded to the UI to drive the "checking" glow.
