# Patchdeck v1.6.1

Release date: 2026-06-01

## Summary
Cleanup release: removes the now-dead JWT authentication path (the app has been cookie-session based since v1.3.0) and the SSE token-in-URL fallback, plus repo hygiene files.

## Removed
- **JWT auth entirely.** `auth.SignJWT` / `auth.ParseJWT`, the `Claims` JWT embed, and the `github.com/golang-jwt/jwt/v5` dependency are gone. Login no longer issues a JWT (returns `{ ok, user }`); the auth middleware accepts only the session cookie (web) or a `pd_` API token (programmatic).
- **SSE `?token=` query fallback.** EventSource auth is cookie-only now (the legacy query path that leaked tokens into logs is removed).
- **`PATCHDECK_JWT_SECRET`** is no longer required or read. Only `PATCHDECK_MASTER_KEY` is required at boot. (Leaving the old env var set is harmless.)

## Added
- `.gitattributes` — forces LF on `*.sh`, `entrypoint.sh`, `*.yml/*.yaml`, `Dockerfile`, `*.go` so CRLF can't sneak into Linux-executed files from a Windows checkout.
- `.trivyignore` — empty by design (CI gates on all fixable HIGH/CRITICAL); documented format for future justified entries.
- `.env.example` rewritten to document the real, current env vars.

## Files changed
- `api/internal/auth/auth.go`, `api/internal/config/config.go`, `api/cmd/server/main.go`
- `api/go.mod`, `api/go.sum` (golang-jwt dropped)
- `.env.example`, `docker-compose.yml`, `docker-compose.ghcr.yml`, `.gitattributes`, `.trivyignore`

## Notes for deployment
- Rebuild image. No API schema or data-migration changes. Existing cookie sessions keep working. `PATCHDECK_JWT_SECRET` in your `.env` is now ignored (safe to remove).
