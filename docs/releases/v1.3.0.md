# Patchdeck v1.3.0

Release date: 2026-06-01

## Summary
Frontend authentication flip (completes the auth refactor started in v1.2.0). The web UI now authenticates entirely via the httpOnly session cookie — the JWT is no longer stored in `localStorage`, and the auth token is no longer passed in SSE/EventSource URLs. This removes a token-disclosure vector (tokens previously appeared in proxy access logs and browser history) and enables real, server-side logout.

## Changed
- **Login** no longer stores a token in `localStorage`; it relies on the `pd_session` httpOnly cookie set by the server.
- **Auth state** is now derived from a `GET /api/me` probe on load (cookie-based), with a brief "Loading…" gate to avoid flashing the login form.
- **API requests** drop the `Authorization: Bearer` header and rely on the same-origin session cookie (`createAuthedFetch`, `useActivity`, `useTOTP`, dashboard tag fetch).
- **SSE/EventSource** (`useStream`, `useRecoveryMonitor`) no longer append `?token=` to URLs — the cookie is sent automatically (`withCredentials`). This is the concrete fix for the token-in-URL leak.
- **Logout** calls `POST /api/logout` (server-side session revocation) in addition to clearing local state.

## Notes for deployment
- Rebuild image. **Users will be logged out once** and must sign in again (the browser's old `localStorage` JWT is no longer used; a fresh cookie session is established on next login). API tokens (`pd_` Bearer) are unaffected.
- Backend already shipped session/cookie support in v1.2.0; this release switches the frontend to use it.

## Follow-ups
- Remove the now-unused JWT issuance/validation (`auth.SignJWT`/`ParseJWT`, `PATCHDECK_JWT_SECRET`) and the SSE `?token=` query fallback in a later cleanup, once no client depends on them.
