# v1.8.9

Service restarts, redesigned around how people actually patch: **one safe "Restart services
safely" button that delegates to needrestart**, with per-service control tucked into an
Advanced section, and a clear recommendation to install needrestart when it's missing.

## Why

v1.8.8 made restarting dbus/logind safe. But the day-to-day flow was still "tick checkboxes
and hit restart" — fine for a power user, needless cognitive load (and a footgun) for everyone
else. The mental model to match is the one users already trust: the `needrestart` prompt after
`apt upgrade`. So Patchdeck now leads with that.

## Change

**Primary action — "Restart services safely"** ([`client.go`](../../api/internal/sshx/client.go), new `RestartAllViaNeedrestart`; `POST /api/hosts/{id}/restart-all`):

- Runs needrestart's own coordinated pass — `needrestart -r a` — the same one that runs after
  an upgrade. It restarts the flagged services in dependency order using their correct restart
  methods, and **automatically skips the units its `override_rc` marks as unsafe to restart
  live** (dbus, all network daemons, docker, display managers, gettys). Those stay flagged and
  surface as reboot-required on the next scan.
- One click, safe by default: it can't lock you out, because it never live-restarts the
  session-critical units.

**Per-service restart → Advanced** ([`HostDetails.jsx`](../../web/src/components/HostDetails.jsx)):

- The checkbox list moves under a collapsed "Advanced — restart individual services"
  disclosure. Risky units (dbus/logind) are **excluded from "select all safe"** and labelled
  *"coordinated · may need reboot"*, mirroring needrestart's own interactive screen. The v1.8.8
  safety still applies if one is chosen (handler-coordinated restart, or refuse → reboot).

**"Install needrestart" recommendation:**

- When a scan finds needrestart absent, Patchdeck now shows a clear callout — *"Patchdeck relies
  on needrestart to detect which services need restarting … install it with `apt install
  needrestart` for full functionality"* — instead of a one-line aside. needrestart is what
  drives both detection *and* safe restart, so it's the recommended baseline, not optional.

## Validation

`needrestart -r a` confirmed non-interactive (no hang without a TTY) and, per its shipped
`override_rc`, skips the dangerous units — validated on the real Debian 13 host `arc`. Both
scanner gates pass; boot smoke reports 1.8.9. Test: `restartAllCmd` (delegates to needrestart,
non-interactive, gated on presence, never a naive `systemctl restart`).

## Notes

- No DB or config-schema change. New endpoint `POST /hosts/{id}/restart-all`; reuses
  `RestartResult`.
- The bulk button is intentionally all-or-nothing (everything safe, in one pass) — that's what
  makes it clean. Granular control lives in Advanced; zero-downtime sequencing lives in
  scheduled maintenance windows.
- `ConfirmDialog` gains an `emerald` confirm color for positive/safe actions.
