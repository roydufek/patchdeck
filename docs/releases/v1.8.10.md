# v1.8.10

Bug-fix: the restart UI now matches what needrestart can actually do — fixing three issues
found testing v1.8.9 on a live fleet. **Frontend-only** (no backend/DB/API change).

## The root cause

needrestart's **detection** (`needrestart -b`, which populates `needs_restart`) lists *every*
service on an outdated binary. But its **restart** pass (`needrestart -r a`, what "Restart
services safely" runs) deliberately **skips** the units in its `override_rc` set — dbus, all
network daemons, docker, display-managers, gettys, `systemd-logind`, and oneshots like
`unattended-upgrades`. It defers those to a reboot.

Patchdeck detected with `-b` but only knew about `dbus`/`logind` as "don't restart" — so every
*other* override_rc unit was shown as restartable, counted as clearable, and offered to a
restart that would never touch it. Result: counts that never cleared, and confusing dead-ends.

## Fixes

1. **Model needrestart's full `override_rc` set** (new `web/src/lib/needrestart.js`, mirrored
   verbatim from needrestart 3.11). Flagged units now split into:
   - **Restartable** — what "Restart services safely" (and an individual restart) actually
     clears. The count and the button act only on these.
   - **Deferred** — units needrestart itself won't live-restart → a new **"Reboot to apply"**
     card lists them with a Reboot button. `dbus`/`dbus-broker` (the only deferred units with a
     coordinated `restart.d` handler) additionally offer an *"Advanced: coordinated restart
     without a reboot"* link. **Fixes the "2 flagged, restart, still 2 flagged" loop.**

2. **`systemd-logind` is deferred, not a dead-end.** It *is* in needrestart's `override_rc`
   (Debian bug #798097 — needrestart won't restart it either), so patchdeck now presents it as a
   clean "reboot to apply" alongside the others, instead of a lone flagged service with a
   restart button that only tells you to reboot. **Fixes the Ubuntu "logind-only" case.**

3. **Stale selection.** `selectedServices` is now pruned (via `useEffect`) whenever a re-scan
   changes the flagged list, so the button count can't drift out of sync with what's shown.
   **Fixes "1 shown / 2 selected".**

4. **Feedback on the safe restart.** "Restart services safely" now seeds the residual-detection
   state, so a restartable unit that stays flagged afterward (e.g. containerd's shims) gets the
   "still flagged → reboot to clear" explanation instead of silence.

## Notes

- Version bump only on the backend. All behavior change is in the frontend; the actual restart
  actions (`needrestart -r a`, and the dbus coordinated handler) were already correct — this
  fixes how their inputs/outputs are presented.
- The override_rc set mirrors needrestart's shipped defaults. A host that customizes
  `override_rc` could differ at the margins; the bulk `-r a` action still does the right thing
  regardless (needrestart applies its own config host-side).
