# v1.8.14

Security patch from a scheduled re-audit (trivy + grype + govulncheck + npm audit).
Clears a CRITICAL + a cluster of HIGH CVEs. **No functional/behavior change** beyond the
version string — purely dependency and base-image hygiene.

## Security

- **golang.org/x/crypto v0.52.0 -> v0.55.0** — clears **CVE-2026-56854 (CRITICAL)**, an
  SSH *server* source-address-restriction bypass in `x/crypto/ssh`. Patchdeck is an SSH
  *client* and runs no server, so it was never reachable (govulncheck confirmed), but it is
  a CRITICAL SCA finding that fails the CI gate. Bump + `go mod tidy` (also pulled x/sys
  0.45->0.47, x/term up).
- **Base image OpenSSL 3.5.7-r0 -> 3.5.8-r0** (alpine 3.22) — the runtime stage `apk upgrade`
  pulls the patched libcrypto3/libssl3, clearing a cluster of ~9 apk CVEs including
  **CVE-2026-63073 (CRITICAL)** plus CVE-2026-18798 / 63076 / 14457 / 14456 / 63072 / 54874 /
  63075 (HIGH). Not exploitable here (CGO-disabled binary does not link openssl), but real
  CVEs in the image; the previously-deployed image predated the 3.5.8-r0 release.
- **npm: nanoid + postcss-selector-parser (both HIGH)** fixed via non-breaking `npm audit fix`
  (lockfile only). Build-time deps that never ship in the runtime image; fixed for a clean
  public `npm audit`. `npm audit --omit=dev` is now 0.

## Deferred
